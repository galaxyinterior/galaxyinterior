# Database Architecture (Firestore)
**Date:** August 21, 2026
**Project:** Galaxy Interior

This document outlines the Firestore data model designed to support the 50-Phase Customer + Admin Platform.

## 1. Core Collections & Relationships

### `users`
Stores user profile information and handles RBAC (Role-Based Access Control).
- `uid` (Document ID) - Firebase Auth UID
- `email` (string)
- `name` (string)
- `phone` (string)
- `role` (enum: 'customer' | 'admin')
- `profilePhotoUrl` (string, optional)
- `address` (map)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)

### `projects`
Stores all customer projects spanning from initialization to completion.
- `projectId` (Document ID)
- `customerId` (string) -> Reference to `users.uid`
- `projectName` (string)
- `projectType` (string)
- `propertyType` (string)
- `location` (string)
- `area` (number)
- `budget` (number)
- `description` (string)
- `requirements` (string)
- `status` (enum: 'Draft', 'Submitted', 'Planning', 'Design', 'Quotation', 'In Progress', 'Completed')
- `assignedTeam` (array of strings)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)

### `projectUpdates`
A subcollection or top-level collection linked to a specific project.
- `updateId` (Document ID)
- `projectId` (string)
- `title` (string)
- `description` (string)
- `images` (array of URLs)
- `attachments` (array of URLs)
- `author` (string)
- `stage` (string)
- `createdAt` (timestamp)

### `pricingCategories`
Admin-managed categories for the dynamic pricing calculator.
- `categoryId` (Document ID)
- `name` (string)
- `description` (string)
- `sortOrder` (number)
- `isActive` (boolean)

### `pricingItems`
Admin-managed items that belong to categories.
- `itemId` (Document ID)
- `categoryId` (string) -> Reference to `pricingCategories.categoryId`
- `name` (string)
- `description` (string)
- `unit` (string)
- `price` (number)
- `pricingType` (enum: 'per_sqft', 'fixed', 'percentage')
- `isActive` (boolean)

### `pricingPackages`
Base packages shown in the calculator (e.g., Basic, Standard, Premium).
- `packageId` (Document ID)
- `name` (string)
- `description` (string)
- `baseRate` (number)
- `unit` (string)
- `features` (array of strings)
- `recommended` (boolean)
- `isActive` (boolean)

### `quoteRequests`
Snapshots of quotes generated by the customer using the calculator.
- `quoteId` (Document ID)
- `customerId` (string)
- `projectId` (string, optional)
- `calculatorInputs` (map)
- `selectedPackage` (map of package snapshot at time of request)
- `selectedItems` (array of item snapshots)
- `taxSnapshot` (map)
- `discountSnapshot` (map)
- `estimatedTotal` (number)
- `status` (enum: 'Saved', 'Requested Detailed Quote', 'Quoted', 'Accepted', 'Rejected')
- `createdAt` (timestamp)

### `supportTickets`
Customer support tracking.
- `ticketId` (Document ID) - Formatted like "GXY-2026-000124"
- `customerId` (string)
- `projectId` (string, optional)
- `subject` (string)
- `category` (string)
- `priority` (enum: 'Low', 'Medium', 'High', 'Urgent')
- `status` (enum: 'Open', 'Under Review', 'In Progress', 'Resolved', 'Closed')
- `assignedSupport` (string)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)

### `supportMessages`
Conversations within a ticket.
- `messageId` (Document ID)
- `ticketId` (string)
- `senderId` (string)
- `senderRole` (enum: 'customer' | 'admin')
- `message` (string)
- `attachments` (array of URLs)
- `createdAt` (timestamp)

### `auditLogs`
Immutable record of sensitive admin operations.
- `logId` (Document ID)
- `adminId` (string)
- `action` (string)
- `resourceType` (string)
- `resourceId` (string)
- `oldValue` (map, optional)
- `newValue` (map)
- `timestamp` (timestamp)

## 2. Security Rules Approach
- **Users**: Read/Write own profile. Admin reads/writes all.
- **Projects/Quotes/Tickets**: Must verify `request.auth.uid == resource.data.customerId`. Admin reads/writes all.
- **Pricing Configuration**: Public reads all. Admin writes all.
- **Audit Logs**: Nobody can update or delete. Only Admins can read. System/Cloud Functions create them.

## 3. Data Integrity & Snapshots
To prevent historical quote corruption (Phase 30 requirement), the `quoteRequests` collection uses **snapshots** rather than references. When a quote is saved, the exact `baseRate` and `price` values from the packages/items at that specific timestamp are duplicated into the quote document.
